| 11 | 2026-09-02 | audit | Self-audit found the compliance-violation counter was structurally incapable of counting (`violations = 0` never incremented) — every "zero violations" claim was vacuous; P4.5 customer memory also never reached the engine's outcome draws or the eval brain's SENSE state, so its personalization was dead in the measured pipeline | Violations now counted from the violation timeline, with a deliberately-illegal-policy test proving the metric moves; profiles flow into `OutcomeModel.draw` and every brain's SENSE state; guardrail fallback made mode-aware; report + dashboard regenerated via new `paypilot-eval`/`paypilot-dashboard` CLIs. | 12 | 2026-09-02 | audit | The voice module was an island: nothing outside `voice/` imported it, so `VOICE_NUDGE` decisions produced no artifact anywhere; the salary-aware script line was dead code (`days_to_salary` hardcoded to None); the strict opt-out/merchant-ID validator never ran on the production path | VoiceNode wired in: the engine now executes VOICE_NUDGE as a safety-validated `VoiceCall` + deterministic timeline entry, and the webhook API returns the generated script (attempting a real test-mode Payment Link first); `days_to_salary` computed from the calendar; strict DR12 gate enforced at the node with template fallback; added `paypilot-live-eval` so the REAL OpenRouter brain can be measured against baseline + doctrine with every decision journaled |
| 13 | 2026-09-02 | demo | The voice demo couldn't PROVE the call was data-driven: the response showed a script but not the strategy behind it, the template ignored customer history entirely, and firing webhooks live required hand-crafted curl + HMAC signing | Template made context-aware (history-aware openers for reliable vs struggling payers, consent-first framing for revoked mandates, truthful reminder line); every voice response now carries a strategy brief (history tone, on-time ratio, days-to-salary, failed attempts, safety re-check); built `/monitor` — a served demo console with one-click failure scenarios signed server-side and browser speech-synthesis playback of the call |
| 14 | 2026-09-05 | voice-hardening | Consent was all talk: the script offered an opt-out but nothing remembered it, so a hypothetical "stop calling" customer could still receive artifacts; scripts had no length cap (an LLM could drone on for minutes); audio was simulated-only (`audio_path` always None) | VoiceNode now has a **do-not-call registry** (`mark_opted_out`/`is_opted_out`) enforced in the engine (timeline `voice_skip` entry), the webhook API (returns a skip notice), and the node itself (raises `DoNotCallError`, zero artifacts) — DR12's offer now has teeth; both validators cap scripts at **120 words (~48s)** with template fallback; added a pluggable **TTS engine** (`voice/tts.py`: `NoopTTS` default, optional `edge-tts` backend behind `uv sync --extra tts`) that renders approved calls to real `.mp3` files + a `paypilot-tts` CLI for the video |
| 15 | 2026-09-05 | fail-loud | The "graceful fallbacks" were actually silent degradations: an LLM brain outage quietly returned a "lawful default" SMART_RETRY, an LLM voice writer failure silently swapped in the template script, and a broken TTS silently dropped audio — a real payments agent that silently executes an action its LLM never justified can charge a customer who revoked consent or call a do-not-call customer. Silence is the danger, not determinism | Fail-loud refactor: `OpenRouterBrain` raises `BrainUnavailable` on outage/unparseable output (graph + `GraphPolicy` escalate the episode to human review with journaled + counted `brain_failures`, never a guess); `LLMScriptWriter` raises `VoiceWriterUnavailable`/`ScriptSafetyError` (no template substitution); `VoiceNode(writer=None)` means the channel is unavailable (`VoiceChannelUnavailable`) and its strict DR12 re-gate raises instead of swapping in the template; the engine records `voice_escalate` timeline entries and closes the episode; the webhook converts an un-executable voice decision to `human_escalation` with a loud `degraded` flag; the live-eval report now surfaces brain failures. Deterministic guardrails + the reference template brain remain as designed components — the eval's measured numbers are untouched (deterministic paths never raise) |
| 16 | 2026-09-05 | memory | The agent had no real memory: customer profiles rode inside event payloads, the ledger was in-memory/JSON, and nothing survived a restart — every demo was a fresh amnesiac. A "recovery agent" that cannot query who it called yesterday or whether consent was revoked is a toy | Built `paypilot/store/`: a SQLite `Store` (customers, subscriptions, mandates, profiles, consent, failure_episodes, decisions ledger, voice_calls, tool_calls) seeded deterministically from the population generator with idempotent re-seeding and an append-only audit; plus `RecoveryTools` — a tool-call layer (`lookup_customer`, `episode_history`, `recent_decisions`, `consent_status`, `next_payday`) where every invocation is timed and written to `tool_calls`, self-describing via `definitions()` and ready for LLM function-calling. Store + tools: 15 new tests |
| 17 | 2026-09-05 | voice-2way | The voice call was a monologue: the agent produced a validated script and played it, but never listened, never adapted, and never closed the loop — a customer saying "I already paid" or "stop the subscription" mid-call was unheard | Built `voice/conversation.py`: a bounded two-way turn loop (hard turn budget so calls never dangle), deterministic intent classification as an *input adapter* (never the decision-maker), context **retrieved via RecoveryTools from the store** at session open, an LLM dialogue brain (`OpenRouterDialogueBrain`) emitting strict JSON `{reply, outcome, note, done}` with a repair round and fail-loud escalation on any brain/network/safety failure, every agent utterance safety-validated before it can be spoken, mid-call opt-out honoured instantly (do-not-call written to the store), and outcomes that are executable (pay_now → payment_link decision, pay_later → salary-timed smart_retry, human → escalation). API: `GET /voice/demo`, `POST /voice/open`, `POST /voice/turn` |
| 18 | 2026-09-05 | dashboard | `/monitor` was a feed, not a control center: three buttons and a scrolling card list, with no way to see the brain's graph, the memory store, or the ledger in one place — the demo forced the judge to trust a wall of text instead of watching the system work | Built the **PayPilot Command Center** at `/command` — a single served SPA (no build toolchain: FastAPI + static HTML/CSS/JS) with eight panels: Overview (live KPI strip incl. a fail-loud alerts counter), Live Recovery (the upgraded monitor feed), Agent Graph (the state machine rendered live with step-by-step state reveal + a one-click "simulate LLM outage" fail-loud trace), Voice Studio (seeded-customer picker + call transcript w/ typed input + mode controls), Memory/DB (live SQLite browser streaming tool-call query events), Ledger (append-only audit), Eval (quick sweep + headline numbers), and a Webhook Lab (compose any signed failure → watch HMAC verify → see the decision). Real-browser smoke test (`scripts/smoke_command_center.py`) walks every panel |
| 19 | 2026-09-05 | dashboard | The Command Center smoke test exposed 500s under the demo's polling: the demo `Store` shared one SQLite connection across FastAPI's threadpool — concurrent reads crashed mid-session | Rewrote `db.py` around a serializing lock (all access funnels through one locked connection with busy-timeout), so concurrent polling is safe; smoke test re-run: all panels green, zero console errors |
